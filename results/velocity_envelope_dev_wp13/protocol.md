# WP 1.3 velocity-informed hold-envelope diagnostic

The procedure is a CPU development sensitivity study requested in the G1 memo, using the six uncorrected packet streams from PR #40 and the frozen candidate in PR #39. The original candidate remains the historical comparator. No paid resources, validation seeds, test seeds or outcome-based choice of parameters are used.

Evaluate every acceleration in {25, 50, 100, 200, 400, 800, 1600} rad/s². The primary diagnostic implements the G1 memo's literal symmetric position interval around the last observed encoder position: radius b_q + |v_s|(age + H) + A(age + H)²/2. A distinct secondary sensitivity uses signed velocity to enclose the position during the hold, using the minimum lower and maximum upper bound from the two endpoints of q_s + v_s*t ± (b_q + A*t²/2) for t in [age, age+H]. These endpoint extrema enclose all intermediate times if the physical acceleration and sensor assumptions hold. Empirical coverage is measurable only at the available recorded positions. Encoder position bounds, joint force limits, requested slew, saturation eligibility, RLS and all other settings are identical to the frozen candidate. Velocity error is zero only for these published simulator channels. H=0.020 s; the predecision sample age is (decision step - 1 - last assimilated source step)*H. No future position or fault label enters the proposed requests.

Run the published gain-set filter and projection on the same states as #40, including the original 10 rad/s bound as a regression control. Measure pooled delivered request magnitude relative to the same-state bounded oracle requested from the recorded zero previous offset, plus the directionally attainable fraction of oracle demand as in #40. Also report the signed, oracle-capped fraction that was actually requested, where wrong-direction effort scores zero. Use alive decisions and preserve censoring. Summarize original first second (offset steps 0–50) and full post-onset horizon by gain, channel and hip/knee group. Pair with per-group two-endpoint coverage from the independently implemented coverage script. Look for ≥99% endpoint coverage and ≥50% requested/oracle in both groups at gain 0.70 with declared telemetry. Distinguish this common-state benchmark from Claude's four-episode replay, which carries its own hypothetical request history, uses a different oracle denominator, and averages per-joint ratios. No bound or method is promoted; the project owner decides G1 after review. Report conditional gain-set and motion assumptions, what source telemetry exists, finite sample limits, and the next discriminating test.
