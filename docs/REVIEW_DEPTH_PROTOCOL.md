# Reviewed depth experiment

This is a new protocol. Historical E17 outputs remain results of the original implementation.
The new evaluator requires a reviewed, protocol-matched response model unless the caller
explicitly requests the legacy-model diagnostic override. It never silently reuses an
existing output directory or treats a saved summary as a cache hit.

## Observation sources

| Source | Position observation | Capture validity | Injected misses |
|---|---|---|---|
| depth | Actual depth image, per-axis surface median plus known sphere radius | Geometric image detector only | image_miss_prob, default zero |
| parametric | True captured centre plus Gaussian noise | Captured launch status, pelvis horizontal cone, range | parametric_miss_prob, default .055 |
| parametric_matched | True captured centre plus Gaussian noise | Same image detector mask as the depth source | image_miss_prob, default zero |

The matched source is explicitly a privileged diagnostic comparator. It asks how changing
the centre estimator affects closed-loop decisions when validity is generated by the actual
image detector. Each arm still observes its own policy-dependent scene; the external
projectile trajectory and reset/scenario draws are paired.

Depth observation construction accepts no projectile launch flag, true position, velocity
or mass. The environment's prelaunch parked projectile is moved to (1000,1000,100) before
all reference and intervention resets. The environment already keeps it at the reset
position until launch. This removes the parked sphere geometrically, without a per-frame
privileged validity gate. True object state is used for the named diagnostic source and
post-hoc measurement-error statistics, not to correct depth observations.

Exact simulator camera/robot pose and freejoint linear velocity are assumed available.
The sphere radius, 0.15 m by default, is known. Height, self-distance, range and minimum
pixel-count masks remain task-specific. This is a simulated, uncluttered geometric detector.

## Time and action contracts

Images are captured when control_step modulo period is zero, and delivered at capture
plus extra_latency. The parametric detector uses the same capture grid and buffers the
launch flag with capture-time pose. Delay 0, 1 and 5 steps at period 5 are included in the
detector tests. Empty deliveries do not fabricate a fresh capture.

The corrected deadline controller locks its predicted arrival and hold at initiation,
respects the minimum commitment and maximum hold, and by default allows one commitment
for the single approaching object. The evaluator passes actual horizon and pelvis heading
to the controller. The belief's future depth observation remains a simplified pelvis-cone
forecast; it does not predict exact future image occlusion or pixel support.

BRACE is masked after a previously latched failure, so post-failure decisions cannot add
preparation time. The first terminating physics interval counts the action actually applied.
Progress includes every physical interval, including the first, and projects each pelvis
displacement on its pre-action heading. Intervals after latched termination are excluded,
matching the common rollout metric.

The reported render_detect_batch_ms times BVH refit, rendering, image-centre extraction
and synchronization for the whole batch. It excludes the belief/controller, actor and
physics. Its wall-clock value is not added to the explicit simulated observation delay.

## Calibration and evidence

The current online estimator is the per-axis median, preserving the latest Session G
upstream correction and matching E8's estimator. Its online errors are still measured;
matching an estimator definition does not independently validate its new distribution.
det_sigma remains an
assumed fixed likelihood parameter. calibration.json records successful-detection bias,
per-axis RMS, pooled-axis RMS and maximum error by range, plus prelaunch detections.
Those measurements are diagnostic and never fitted back into the evaluated controller.
Fitting a new likelihood requires a separate development set and a fresh test run.

Every arm saves all episode outcomes with explicit scenario IDs, source/method, physical
mass/speed, hit/miss label, contact and failure times, first detection capture/delivery,
brace onset/release, brace at contact, switch count, duration, progress and recovery
censoring. The common statistics module pools integer numerators and denominators and
calculates scenario-paired differences with approximate 95% intervals. These intervals
condition on the frozen skill pair and do not measure across-training-seed variability.

Detailed per-step decision and timestamp traces are saved for trace_episodes scenarios per
batch (default eight). All outcomes, including those outside the trace subset, are retained.
config.json records source/checkpoint/model hashes, exact overrides and observation
assumptions. summary.json is written with status complete only after all requested arms,
paired outputs and calibration records finish.

## Validation available before the pod

The shared detector geometry, timestamp queue and error accumulator have eleven NumPy/CPU
tests. Four real-JAX tests cover capture validity/phase, buffer bounds, JIT agreement with
NumPy geometry, and a two-world external-detection controller JIT exercising TTC, lead,
blind-wait and observation-lookahead methods. All fifteen passed on an isolated CPU
environment with JAX/JAXLIB 0.12.0.1. They are explicitly skipped if JAX is unavailable;
the pod preflight must run them before the GPU experiment. MuJoCo rendering and policy
integration still require the bounded pod gate; passing these CPU checks is not a
claim that those integrations ran.
