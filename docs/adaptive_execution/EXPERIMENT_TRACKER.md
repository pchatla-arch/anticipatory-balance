## 2. Current empirical findings and unresolved controls

S1a gain 0.70: mean velocity tracking loss **0.085517** (no correction), **0.038328** (heuristic), **0.031378** (inverse estimator), **0.028719** (privileged oracle). Heuristic reduces loss by ~55.2% versus none; recorded forward distance is **2.4409 m vs 3.6219 m**. **The previous interpretation of that distance reduction as a performance penalty was unsupported.** The [raw-trace segment audit](review_audits/2026-11-26/s1a_segment_audit.json) shows no-correction stop-phase velocities of 0.329/0.349 m/s despite a zero command, versus 0.054/0.274 m/s with the heuristic. Some extra distance is unwanted motion; the heuristic's stopping improvement is inconsistent. Neither aggregate distance nor loss alone proves superior navigation.

Gain 0.70 then restoration: heuristic loss **0.036317** versus none **0.061005**; corrected offset withdrew in **2 of 2** episodes, median **5.5 control ticks (~110 ms)**. Estimated inverse never withdrew in **2 of 2**. Report denominator, not only the conditional median.

Sensor-scale confound (healthy gain, effort readings ×0.8): no correction loss **0.026801**; heuristic **0.031044** (worse), healthy harmful correction **0.043697 rad**. Inverse estimator harmful correction **0.107939 rad**. This is a **negative result** on sensing ambiguity, not a safe adaptation guarantee.

All S1a episodes have **0 falls / 32**, but only two paired scenarios per cell: no generalization or population-confidence claim. No physical G1 hardware experiment.

S1b CPU-only work: the CSV summaries and eight-episode segment audit are complete; extend phase-wise plots/metrics to the other saved traces, retain missed-restoration denominators and nuisance-sensor harms, and distinguish commanded-motion fidelity from raw distance. A sensor-confidence abstention rule is a candidate for a separate evaluation, **not** a measured solution. A new model training or held-out test should not be assumed from the existing development data.

**G2a verification:** Real G1 scene check sourced from `15bfd72603d5dac6cecaf2d3cc192d0d10904291` ran in Secure A6000 pod `e9tnqh3jnvdwww`; the CPU MuJoCo model compiled with 29 actuators, two cameras, four explicit static-obstacle contact pairs, zero contacts in the start pose and four contacts under an evaluation-only overlap. The first attempt using raw XML loading failed to resolve a Menagerie asset path; using the same `AdaptiveJoystick` environment asset loader as S1a fixed it. The successful test exited 0 and the RunPod provider verified `EXITED`. **This does not establish closed-loop obstacle detection or route completion.**
